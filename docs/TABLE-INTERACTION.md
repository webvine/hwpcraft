# 표 선택·이동·크기 조절 수정 (2026-10-24)

## 원인

- 셀 안 클릭은 텍스트 커서/셀 블록만 선택했습니다. 전체 선택은 표 디자인 탭의 별도 명령으로만 진입할 수 있었습니다.
- 전체 표를 끌어 이동하는 입력 처리와 엔진 명령이 없었습니다.
- 일반 격자선 크기 조절은 egui가 드래그 임계값을 넘긴 시점의 현재 포인터를 3 px 경계선 범위와 비교했습니다. 빠른 드래그는 경계 밖에서 시작한 것으로 판정되어 셀 블록 선택으로 넘어갔습니다.
- 네이티브 입력에서 누름+이동이 같은 UI 갱신에 도착하면 `drag_started/dragged/drag_stopped`가 모두 false가 되는 경우를 실제 창 진단 로그로 확인했습니다. 기존 손잡이 경로도 이 신호에만 의존하여 작동하지 않았습니다.

## 수정

- 표 위에 포인터를 올리거나 표 안에 커서를 두면 왼쪽 위에 십자 손잡이를 표시합니다. 클릭하면 전체 선택, 끌면 이동합니다.
- 선택된 표 외곽도 끌어 이동할 수 있습니다. 오른쪽·아래·오른쪽 아래 파란 사각 손잡이는 크기 조절, Shift는 비율 유지입니다.
- 셀 안을 클릭하거나 드래그하면 본문/셀 블록 편집으로 돌아갑니다. Esc는 전체 선택을 해제합니다.
- 경계선과 손잡이는 원시 포인터 누름/놓기 이벤트를 사용하고, 클리핑된 페이지 및 최상위 레이어로 입력 소유권을 검사합니다. 빠른 입력과 한 프레임 안의 누름·이동·놓기를 처리합니다.
- `table.move`는 UI·CLI·MCP 공통 엔진 명령입니다. 실제 조판 위치와 바깥 여백을 반영하고, 이동 한 번을 한 Undo 단계로 기록합니다. 실패하면 문서와 Undo 기록을 보존합니다.
- 글자처럼 취급한 표는 이동할 때 떠 있는 표(위아래 배치)로 바뀝니다. 본문과 셀 크기는 유지합니다.

## 검사

- 엔진: 일반/글자처럼 취급한 표 이동, 바깥 여백, 유니코드 내용, Undo/Redo, HWP·HWPX 저장 후 위치·크기 보존, 쪽 밖 이동 실패 원자성.
- egui 이벤트: 십자 손잡이로 선택·이동 → 크기 조절 → 두 번 Undo; 빠른 셀 경계 드래그; 한 프레임 안의 전체 드래그; 실제 리본·스크롤 영역·포커스·대화상자를 포함한 페이지 흐름.
- 실행 로그: `logs/table-move-engine.log`, `logs/table-move-ui.log`, `logs/table-move-tests.log`, `logs/table-move-clippy.log`.

## 범위

직접 이동은 한 쪽 안의 최상위 표만 지원합니다. 중첩 표 및 여러 쪽에 걸친 표의 드래그 이동은 지원하지 않습니다. 내용보다 작은 셀 높이는 조판 과정에서 커질 수 있습니다. 아래한글과 완전한 조판 일치를 뜻하지 않습니다.
