# HwpCraft 0.18 — 차트 만들기·MCP Tasks·편집 속도·화면 정리

0.18 릴리스. 아래한글 전체 기능의 100% 호환을 뜻하지 않는다.

## 기능

- 새 차트: 세로 막대·가로 막대·꺾은선·원·도넛·분산·주식(고저종가, 시가고저종가)·3차원 세로 막대·3차원 가로 막대·3차원 원 11종을 공통 엔진 `chart.create`/`chart.configure`로 만들고 고친다. 화면은 왼쪽 설정·데이터 표, 오른쪽 실시간 미리 보기의 2단 창이다. 자체 HWP/HWPX 저장·재열기와 PNG/PDF 표시를 검사했지만, 실제 한글에서 차트가 원래 차트로 열리는지(한컴 고유 차트 호환성)는 검증하지 않았다. 한컴 표본·서식·리소스는 복사하지 않는다.
- atomic batch: 명령 하나가 실패하면 문서뿐 아니라 실행 취소/다시 실행 기록, 본문·셀 클립보드, 쪽 클립보드까지 batch 시작 전으로 되돌린다. 되돌리기에 실패한 문서는 다시 쓰지 않고 오류로 남긴다.
- MCP 문서 열기는 새 문서를 따로 준비한 뒤 바꿔 끼우므로, 열기에 실패해도 열려 있던 문서는 그대로 남는다.

## MCP 2026-07-28

- Tasks 확장(`io.modelcontextprotocol/tasks`): 확장을 선언한 클라이언트는 문서 열기·저장·PDF 내보내기를 task로 받아 `tasks/get`으로 완료를 확인하고 `tasks/cancel`로 취소한다. 파일을 교체하기 전에 취소한 저장은 기존 파일을 남긴다. 폴링 전용이며 상태는 프로세스 메모리에만 있다.
- 도구 15개 모두 결과 형식(`outputSchema`)을 선언한다. `progressToken`을 준 호출은 실행 중 5초마다 경과 시간 진행 알림을 받는다. 모든 결과의 `_meta`에 서버 정보(`io.modelcontextprotocol/serverInfo`)를 넣는다.
- 오류 코드: completion 빈도 제한 -32901 → -31429, 문서 구독 한도 -32901 → -31503(2026-07-28 예약 범위와 겹치지 않게). 2025년 판 클라이언트의 initialize는 -32022 `{supported:["2026-07-28"]}`로, HTTP에서 `MCP-Protocol-Version` 헤더가 없는 POST는 400으로 거절한다.
- 16개 문서가 모두 열려 있으면 30분 넘게 쓰지 않은, 수정되지 않은 문서 하나를 닫고 새 문서를 연다. 수정된 문서는 자동으로 닫지 않는다.
- 쪽 이미지(`render_page`) PNG를 무손실로 더 압축해 응답이 최대 60% 작아졌고, 이미지 결과는 복사하지 않고 옮긴다. 명령 목록 응답 16.3 → 4.8 ms. stdio 서버는 RHWP 조판 진단 출력을 꺼서 stderr가 비어 있다.
- 공식 Python SDK 2.3.0으로 stdio·HTTP 53/53 통과, TypeScript client 2.4.0은 41/43(실패 2건은 TS SDK가 Tasks 결과를 아직 해석하지 못하는 SDK 한계로, 확장을 선언하지 않으면 영향 없음). 쓰지 않던 이전 `server.rs`를 지웠다.

## 성능

수치는 release 빌드에서 381쪽 공문 편람 샘플로 잰 값이다. 바꾼 뒤에도 저장 바이트·쪽 화면·실행 취소 결과가 같은지 표본 문서로 비교했다.

- MCP로 새 문서에 150절(44쪽) 보고서를 쓰는 전체 흐름 32.4초 → 8.1초. 여러 문단을 한 번에 넣는 입력(`text.insert`, MCP `type_text`, 붙여 넣기)은 쪽 나눔을 끝에서 한 번만 한다(합계 14.6초 → 1.9초).
- 글자 모양을 바꿀 때 문서 전체를 복사해 다시 조판하던 것을 고친 문단만 다시 배치한다(RHWP 패치 0005·0006). 문단 끝 Enter 232 → 10 ms, 대기 서식 지정 499 → 22 ms, 그 뒤 첫 글자 473 → 13 ms, 선택 51문단 굵게 616 → 137 ms. 이전에 한 쪽 틀리게 세던 쪽 수(380 → 381)도 다시 연 결과와 같아졌다.
- 열기: 쪽 번호·자동 번호 보정을 첫 조판 전에 적용해(RHWP 패치 0007) 중복 조판을 없앴다. .hwp 769 → 437 ms, HWPX 971 → 395 ms.
- 표 셀 반복 편집(표 마당·음영·계산·정렬·자동 채우기 등)과 모두 바꾸기·한자 일괄 변환은 쪽 나눔을 한 번으로 묶는다(206셀 표 마당 13.9초 → 0.43초). atomic batch 되돌리기 약 700 → 250 ms.
- PDF: 쪽을 최대 8개 스레드에서 병렬 변환해(RHWP 패치 0002, 출력 바이트 동일) 381쪽 저장 84초 → 약 17초(최대 메모리 약 1.9 GB, `RHWP_PDF_THREADS`로 조절). 저장 뒤 쪽 렌더 캐시를 비워(패치 0003) 메모리가 738 → 75 MB로 돌아온다. PDF 준비는 프레임마다 나눠 진행해 화면 정지가 2초대에서 약 60 ms로 줄었고 상태 표시줄에 진행 쪽수를 보인다.
- 화면: 같은 쪽은 다시 그리지 않고(89–256 ms → 1–2 ms), 입력 때 줄 배치가 그대로면 캐럿 문단 띠만 다시 그린다. 큰 내장 그림은 화면 배율에 맞춘 대체본으로 그려 키 입력 프레임 중앙값 약 130 → 78 ms. 글꼴 데이터베이스를 공유해 첫 렌더 100 → 34 ms.

## 화면

- 지원하지 않는 리본 명령은 기본으로 숨기고 탭 끝 "지원 안 함 n"에서 이름과 사유를 보인다(보기 설정에서 다시 표시). 기능이 있는데 막혀 있던 "차트 만들기"와 도구 탭 "블록 계산"(합계·평균·곱)을 켰다.
- 툴팁에 단축키를 함께 적고, 지원하지만 지금 쓸 수 없는 명령은 이유를 보인다("글자를 먼저 선택하세요" 등). 명령 목록에 적혀 있던 연속 키(Ctrl+N,A 표 나누기, Ctrl+K,H 하이퍼링크 등)를 모두 실제로 동작하게 했다.
- 메모는 오른쪽 고정 패널(너비 조절 가능)로 본문을 가리지 않는다. 메모 입력칸에 포커스가 있을 때만 문서 단축키가 멈춘다.
- 개체·도형·글상자·각주/미주·스타일·개체 목록·양식 개체 등 대화상자를 공통 틀(제목줄·오른쪽 확인/취소·Enter/Esc)로 맞췄다. 파일 탭 최근 문서는 이름과 줄인 폴더로 보인다. 상태 표시줄의 변경 기록 칸은 HWP 변경 추적 기록이 있는 문서에서만 보인다. 2배 확대 때 텍스처 크기 한도로 멈추던 문제를 고쳤다.

## 검증과 한계

Windows x64에서 `cargo test --locked --workspace`(632 통과, 0 실패)·`cargo clippy --workspace --all-targets -D warnings`와 실제 데스크톱 화면 90종 캡처를 확인했다. macOS(arm64·x64)와 Linux x86_64는 GitHub Actions 릴리스 빌드에서 workspace 테스트를 실행한다. RHWP 로컬 패치 0001–0007은 `patches/rhwp/`에 MIT 라이선스 그대로 기록하며, 깨끗한 RHWP v0.8.7에 순서대로 적용하면 빌드에 쓴 RHWP와 같아진다. HWPX의 변경 추적 목록은 읽지도 보존하지도 않는다(HWP 파일의 변경 추적 기록은 저장 때 보존). 실행 취소는 아직 문서 전체를 다시 조판한다(381쪽 약 250 ms).
