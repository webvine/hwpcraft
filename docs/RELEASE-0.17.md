# HwpCraft 0.17 — 입력 서식·문서 영역·표시 조판

0.17 릴리스. 아래한글 전체 기능의 100% 호환을 뜻하지 않는다.

- 선택 없는 글자 모양 변경은 이후 입력에 적용한다. 기존 글자의 서식을 확장해서 바꾸지 않는다. 실제 한글 공개 자동화로 확인한 입력 위치·선택·문단 나누기·undo/redo 동작을 공통 엔진에 반영했다. 문서에 남는 빈 문단/끝 모양과 일시적인 입력 대기 모양을 구분한다.
- 편집 탭의 **문서 영역 편집**에서 머리말·꼬리말·가로 글상자·각주·미주 및 혼합된 중첩 영역의 텍스트와 글자/문단 모양을 주소로 편집한다. 오래된 주소와 보호 영역의 변경은 거절한다. 세로 글상자와 캔버스에서의 직접 편집 등은 별도 구현 범위다.
- 새 글상자가 포함된 HWP를 실제 한글이 읽을 때 본문까지 사라지던 저장 문제를 자체 형식 어댑터로 고쳤다. 원본 모델이나 HWPX를 바꾸지 않고 HWP의 글상자 목록 표시를 보정한다.
- 가져온 중첩 표의 조상 프레임이 짧아 내용이 잘리는 경우, 표시 전용 복제본의 크기를 조정한다. 원문 파일·편집 모델·문서 서식은 보존한다. 고정/잠긴 크기, 세로쓰기, 캡션, 여러 쪽에 걸친 표 등은 보정 대상에서 제외하고 진단에 남긴다.
- 공통 표시 좌표 캐시로 본문 번호 조판의 반복 계산을 줄이고, 한 문단이 여러 쪽에 걸칠 때 쪽 시작/끝 이동과 클릭 위치를 구분한다. 화면 탐색용 힌트는 문서 데이터와 분리한다.
- 형광펜은 캐럿 위치에 영향을 받지 않는 표시 글자 좌표를 사용한다. 전체 쪽 export는 원문을 보존하고, 일부 쪽의 문단·표·구역을 정확하게 제외할 수 없으면 기존 출력 파일을 보존한 채 거절한다.
- 상용구·스타일·그림 파일에도 자동화 읽기/쓰기 폴더 제한을 적용한다. atomic batch는 외부 파일·설정 쓰기를 시작 전에 거절하며 문서 변경만 복구한다. 그림 일괄 저장은 모든 대상의 권한·충돌을 미리 확인하고 각 파일을 원자적으로 저장한다.
- 서식 미리 보기와 CLI 시작 문서는 새 입력 서식 의미에 맞게 샘플 서식을 적용한다. 설치 전 GUI와 CLI의 빌드 버전이 소스 버전과 일치하는지 검사한다.

Windows x64에서 `cargo test --locked --workspace`·`cargo clippy --workspace --all-targets -D warnings`와 실제 데스크톱 실행(381쪽 문서)을 확인했다. Linux x86_64는 WSL Ubuntu 24.04에서 workspace 테스트를 실제로 실행했고, macOS arm64는 교차 check·clippy만 확인했다(실제 Mac 미확인). HWPX 자체 재열기와 실제 한글에서의 HWPX 직접 열기 검증은 구분한다. OS IME·하드웨어 키 입력·Launcher 버튼 직접 클릭은 Windows UI 연결 문제로 미검증이다.

## 소스 검토·안정성·성능 개선

새 기능 없이 오류 수정·최적화·화면 정리만 한 묶음이다. 수치는 release 빌드에서 381쪽 공문 편람 샘플로 잰 값이다.

- 열기 멈춤 해결: 중첩 표 표시 보정이 정해진 작업량 안에서만 실행된다(같은 문서는 항상 같은 결과). 90초를 넘던 문서가 0.2–2초에 열린다. 한도를 넘는 표는 원본 배치로 표시하고 보고서에 사유를 남긴다.
- 편집 지연: 보정할 것이 없던 문서는 다음 편집에서 같은 판정을 다시 쓴다. 중첩 표 문서의 글자 입력 후 쪽 수 계산이 247 ms–2.1초에서 2 ms 아래로 줄었다. 표시 보정 실패도 같은 편집 상태에서는 다시 계산하지 않는다. 쪽 번호 필드가 있는 문서는 본문 글자 입력·삭제를 표시용 문서의 해당 문단에만 반영해(검증용 debug 비교 포함), 381쪽 문서의 입력 후 쪽 수 계산이 약 800 ms → 40 ms가 됐다. 문단 나누기 등 다른 편집은 전체 재조판(약 0.3초)한다. 화면 렌더러는 시스템 글꼴 파일을 한 번만 매핑해 공유한다(render 크레이트에 한정한 unsafe, 렌더 결과는 픽셀 단위로 같음). 편집 후 한 쪽 다시 그리기 564 ms → 153 ms, 40쪽 그리기 14초 → 5초.
- 선택 강조: 글자마다 캐럿 위치를 두 번 묻던 그리기를 줄 단위 계산과 쪽별 캐시로 바꿨다(전체 선택 한 쪽 17초/프레임 → 첫 계산 1.5초, 이후 0).
- 모두 바꾸기 1,273곳 82초 → 2.8초(조판을 끝에서 한 번), 바꿀 필요 없는 일치는 편집하지 않는다. 메모 만들기·고치기 372 ms → 21 ms. 리본·표·개체 화면의 매 프레임 문서 훑기를 편집 단위 캐시로 바꿨다.
- 손상 파일: 행·열 수가 실제 셀보다 작게 기록된 표를 열 때 보정해, 화면 그리기에서 앱·MCP 서버가 종료되던 문제를 막았다. 쪽 번호 자리표가 예상과 다른 문서도 열린다. HWPX 압축 해제 한도는 ZIP에 적힌 크기 대신 실제로 푼 크기로 세고 구역 항목 수를 제한한다.
- 자동화 보안: atomic batch 안에서는 파일·설정 쓰기를 쓰기 검사 단계에서 모두 거절한다. 문서 비교는 폴더 제한을 파일 존재 확인보다 먼저 검사한다.
- 그 밖의 수정: 각주·미주 장식 문자는 HWP에 저장할 수 있는 문자만 받는다. 표 선택 패널은 바뀐 치수만 적용한다. 상용구 준말이 다른 항목과 겹치지 않는다. 세로 글상자 리본 항목이 활성화된다.
- 화면: 파일 탭에 명령 목록과 최근 문서를 둔다. 아직 지원하지 않는 리본 항목은 회색과 함께 이유를 툴팁으로 보인다. 중첩 표 편집과 문서 영역 편집을 한 메뉴로 묶었다. 글꼴 상자 폭, 시작 안내 문구, 표 디자인 탭 묶음, 찾기 창 위치·결과 수, 개체 목록 표, mm 값 표시 자릿수를 정리했다.
- 빌드 설정 비교: opt-level 3·thin LTO·codegen-units 1은 쪽 그리기 약 25% 개선, 열기·PDF는 차이가 없고 빌드 시간이 3.5배라 release 설정은 그대로 둔다. PDF 저장은 RHWP가 글리프마다 글꼴 파일을 다시 매핑하던 비용을 로컬 RHWP 패치(patches/rhwp/0001)로 없애 381쪽 문서 372초 → 84초가 됐다(출력 PDF는 바이트 단위로 같음). RHWP 로컬 패치는 patches/rhwp/에 기록하고 scripts/sync-siblings.ps1이 RHWP 최신화 뒤 다시 적용한다.

## MCP와 플랫폼

- MCP는 2026-07-28 규격 전용 서비스로 바뀌었다. 요청마다 프로토콜 메타데이터와 문서 작업의 명시적 `document_id`를 쓰고, 문서마다 별도 작업자에서 실행한다. 이전 연결 방식은 지원하지 않는다.
- HTTP 전송(`--transport http`)은 loopback 주소에서만 열리며 모든 요청에 `Authorization: Bearer <토큰>`이 필요하다. 토큰은 설정 폴더의 `mcp-http-token` 또는 `--auth-token-file`로 지정한 파일에 있고, 없으면 서버가 무작위로 만들어 본인만 읽을 수 있게 저장한다. 토큰이 없거나 틀린 요청은 경로와 관계없이 401로 거절한다.
- macOS에서는 단축키가 Ctrl 대신 Cmd로 동작한다(메뉴 표기는 아직 Ctrl). 설정 폴더는 OS 표준 위치를 쓰고, Linux 클립보드 붙여넣기, 한글 글꼴이 없는 Linux에서 영문까지 사라지던 문제, 인쇄(Windows 인쇄 동사, macOS·Linux CUPS `lp`)를 고쳤다. macOS `.app` 묶음과 Linux `.desktop`·`install.sh`를 배포 묶음에 넣었다. macOS 앱은 서명·공증하지 않았다.
- 배포 묶음의 `licenses/`에 의존 크레이트의 추가 고지(subsetter, svg2pdf, cfg_aliases)를 넣었고, RHWP 로컬 패치는 `patches/rhwp/`에 MIT 라이선스 그대로 기록한다.
