# HwpCraft 0.16 — 메모·중첩 표·동적 번호

HwpCraft 공통 엔진에 본문 메모, 중첩 표의 주소 기반 편집, 본문 자동 번호 조판과 공개 자동화 인자 일부를 추가했다. 아래한글 전체 기능의 100% 호환을 달성했다는 의미는 아니다.

- 메모: 본문 한 문단의 선택 범위 또는 커서에 생성하고, 작성자·여러 줄 메모 본문을 고치거나 삭제한다. undo/redo와 문서 변경 감지를 제공한다. HWP 메모 저장은 불필요한 끝 빈 문단을 제거하고 관계없는 스트림·메타데이터를 보존한다. 암호 저장에도 같은 보정을 적용한다.
- 중첩 표: 편집 탭의 **중첩 표 편집**에서 임의 깊이 셀의 문자/문단 서식, 텍스트, 문단 나누기·합치기, 새 표 생성·삭제를 수행한다. 보호된 하위 개체와 내용이 있는 캡션을 확인하고, 구조 편집 후 커서·선택을 보정한다.
- 자동 번호: 본문 쪽 번호·전체 쪽수를 실제 글자 모양으로 측정해 자리를 예약하고 화면·PNG·PDF에 그린다. 쪽 이동·통계·객체 좌표도 같은 표시 조판을 사용한다. HWPX 번호 모양은 압축된 번호 코드로 잘못 변환되지 않도록 자체 어댑터로 보존한다.
- 공개 인자: `CharShape`, `ParagraphShape`, `TableCreate`의 일부 인자를 `hwp.parameters.apply`와 MCP `hwp_action.parameterSet`으로 받는다. 지원 필드는 `hwp.parameters.schema`로 조회하며 미지원 인자는 편집 전에 거절한다. 글자 모양은 혼합 서식의 다른 언어별 속성을 보존한다.

실제 한글의 별도 숨김 인스턴스에서 자체 메모 문서와 3단 중첩 표 문서의 HWP 가져오기·내보내기를 확인했다. 한국어·이모지, 메모 작성자·내용·앵커, 중첩 표의 굵기·글자 크기를 확인하고 한글이 내보낸 파일을 HwpCraft에서 다시 검사했다. 일반 문서 전체의 픽셀 단위 조판 동등성을 뜻하지 않는다.

남은 범위는 메모 답글·해결 상태·셀/여러 문단 앵커, 중첩 표의 캔버스 직접 선택·끌기, 머리말/글상자/주석 편집 문맥, 표 내부 동적 번호, 선택 없는 입력 대기 글자 모양 등이다. 번호 때문에 쪽 경계가 달라진 HWP/HWPX/TXT 쪽 추출은 아직 거절하며 PDF 쪽 저장은 지원한다. 새 메모의 실제 한글 HWPX 직접 열기 검증은 남아 있다. 전체 기능의 상세 한계는 README와 기능 확장 문서를 따른다.

검증: workspace 테스트 277통과·0실패·2진단용 제외, Clippy 전체 타깃 통과. 린트 보정 후 엔진/UI 단위 검사 39개도 통과했다. 실제 데스크톱에서 메모 목록/본문, 중첩 표 편집/본문, 번호 모양 16종, 번호 재조판 화면을 캡처해 확인했다. PDF의 3단 표는 전체 문자열 추출과 raster 가시성을 확인했다.

수정 없이 가져온 기존 짧은 프레임의 중첩 문서는 깊은 내용이 잘릴 수 있다. 입력 대기 모양·문맥 확장·공통 좌표 캐시의 다음 단계 코드는 아직 제품 경로에 등록하지 않았으며 이 버전의 지원 기능으로 집계하지 않는다. Launcher 버튼 직접 클릭 검증은 Windows UI 도구의 native pipe 연결 실패(os error 2)로 남아 있다. 로컬 등록 실행 경로는 별도로 확인한다.
